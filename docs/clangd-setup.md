# Clangd LSP Setup for UETPFCore

Clangd provides accurate code navigation, go-to-definition, find-references,
rename, autocomplete, and real-time diagnostics for C++. For a project the size
of UE5, it dramatically outperforms Microsoft's IntelliSense parser in accuracy
and response speed.

Two things are required:
1. `clangd.exe` on your PATH (ships with Visual Studio 2022)
2. `compile_commands.json` at the project root (generated by UBT)

---

## How it works

`Scripts/gen_clang_db.bat` runs UnrealBuildTool in `GenerateClangDatabase` mode
against the `SinglePlayerStoryTemplateEditor` target. That target transitively
compiles all modules in this workspace — `UETPFCore`, `GameLauncher`, and
`SinglePlayerStoryTemplate` — so the generated database covers every source file.

The database contains the exact compiler invocation for each `.cpp` file: include
paths, defines, flags. When clangd encounters `#include "Engine/World.h"` it
resolves the path using those flags and indexes the engine header in place.
**Engine source navigation (jump to UE class definitions, etc.) works automatically**
— no separate setup needed.

---

## Prerequisites

- Visual Studio 2022 with **Desktop development with C++** workload
- Unreal Engine 5.7 installed
- VS Code with the [clangd extension](https://marketplace.visualstudio.com/items?itemName=llvm-vs-code-extensions.vscode-clangd)
- Project must compile successfully before generating the database

---

## Step 1 — Add clangd to PATH

Visual Studio 2022 ships clangd but does not add it to PATH automatically.

1. Open **Windows Settings → System → About → Advanced system settings → Environment Variables**
2. Under **User variables**, select `Path` and click **Edit**
3. Click **New** and add:
   ```
   C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\Llvm\x64\bin
   ```
   > Adjust the path for Enterprise/Professional editions or non-default install locations.
4. Click OK, then **restart VS Code** for the PATH change to take effect

Verify by running `clangd --version` in a terminal.

---

## Step 2 — Generate compile_commands.json

```batch
Scripts\gen_clang_db.bat
```

This writes `compile_commands.json` to the project root. The file is gitignored —
every developer generates their own copy locally.

### When to regenerate

- After `git clone` (first setup)
- After modifying any `Build.cs` file
- After adding or removing a module
- After switching to a branch with different source structure

---

## Step 3 — Configure VS Code

### Install the clangd extension

Search for `llvm-vs-code-extensions.vscode-clangd` in the Extensions panel and install it.

### Disable Microsoft IntelliSense (keep the C/C++ extension)

If you have the Microsoft C/C++ extension installed, keep it — you need it for MSVC
debugging. But disable its IntelliSense engine so it doesn't conflict with clangd:

Add to your `.vscode/settings.json` (`.vscode/` is gitignored, so this is personal):

```json
{
  "clangd.arguments": [
    "--compile-commands-dir=${workspaceFolder}",
    "--background-index",
    "--header-insertion=never",
    "--log=error"
  ],
  "C_Cpp.intelliSenseEngine": "disabled"
}
```

**What each setting does:**
- `--compile-commands-dir` — tells clangd where to find `compile_commands.json`
- `--background-index` — indexes the full codebase in the background on first run
- `--header-insertion=never` — stops clangd from auto-inserting includes on completion
- `--log=error` — suppresses clangd's verbose output in the VS Code output pane
- `C_Cpp.intelliSenseEngine: disabled` — disables the conflicting Microsoft parser;
  the C/C++ extension still provides MSVC debugging, disassembly, and memory views

### Multi-root workspace (repo + engine source)

If you have both the project and UE5 engine source open as workspace folders in
VS Code, clangd's background index will cover both. No extra config needed — the
`compile_commands.json` already contains the engine include paths, so clangd
follows `#include` directives into the engine tree automatically.

## Troubleshooting

**"No compile commands found"**
Run `Scripts\gen_clang_db.bat`. Verify `compile_commands.json` exists at the
project root.

**Errors in generated headers (`*.generated.h`, `ObjectMacros.h`)**
These come from UE's reflection macros. The `.clangd` config at the project root
suppresses the most common ones. If new patterns appear, add them to `.clangd`'s
`CompileFlags.Add` list.

**"clangd: command not found"**
VS Code needs to be restarted after PATH changes. Run `where clangd` in a new
terminal to verify the path is set.

**Clangd is slow to start the first time**
Background indexing of UE5 headers takes several minutes and uses CPU. The index
is cached in `.cache/clangd/` (gitignored). Subsequent launches are near-instant.

**Go-to-definition goes to wrong overload**
Make sure `compile_commands.json` is up to date. Stale databases cause clangd to
use the wrong preprocessor state.
